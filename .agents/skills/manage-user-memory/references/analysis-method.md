# 情境人格与潜意识分析方法

## 分析阶梯

1. 直接陈述归为 `fact`。
2. 跨交互重复出现的行为归为 `observation`。
3. 对行为原因的解释归为 `hypothesis`，即使解释看似明显也不得越级。

## 情境人格

- `core.md` 保存跨情境稳定特征和共同基线。
- `contexts/<context>.md` 保存该情境独有的目标、偏好、语气和 AI 回应方式。
- 选择顺序为用户明确指定、任务语义判断、仅使用核心人格。
- 只从同一情境的证据更新对应人格，不跨情境复制偏好。
- 娱乐人格等证据不足时保留“待学习”，不得补写想象内容。

## 潜意识假说

- 从可观察行为出发，不从刻板印象出发。
- 同时写出最强替代解释，避免单一叙事自我强化。
- 写明未来什么证据会降低或推翻该假说。
- 新证据矛盾时降低置信度或删除，不为维护旧画像而曲解证据。

## 本地对话历史取证

- 仅在用户授权后读取 Codex、GitHub Copilot、Claude Code、OpenCode、Grok 等本地历史。
- 只接受框架明确标记的用户 Prompt；排除 AI 回复、系统/开发者包装、工具输出和明显转载。
- 先按框架内完全相同文本去重，再以跨时间、跨项目或跨框架重复模式形成观察。
- 不把完整 Prompt 语料写入 memory；只保存统计、短证据摘要、限制和可复核来源类型。
- 检测到密码、令牌、私钥或其他秘密时跳过，不进入分析结果和日志。

## 工作经验门槛

经验若只对当前用户、仓库或阶段有价值，保留在 `work/lessons.md`；只有形成稳定、通用、可执行流程后，才考虑升级为 Skill。
