# 管理用户记忆

先读取 `.agents/memory/INDEX.md` 与 `governance/evidence-policy.md`。涉及人格时读取 `user/personality/INDEX.md`，再按当前情境加载 `core.md` 和一个情境文件。格式见 [memory-schema.md](references/memory-schema.md)，分析边界见 [analysis-method.md](references/analysis-method.md)。

## 工作流

1. 优先采用用户明确说明的情境；否则按任务内容选择，无法判断时只用核心人格。
2. 用情境人格覆盖当前交互的偏好、语气和回应方式，不改写核心人格与背景事实。
3. 深度画像经用户授权后，可读取 Codex、Copilot、Claude Code、OpenCode、Grok 等本地历史；只提取用户 Prompt 字段，排除 AI 回复、系统包装和明显转载。
4. 在实质性交互结束时识别长期候选；没有候选则不写入。
5. 将候选路由到对应叶子，标注事实、观察或假说，并记录依据、限制、日期与置信度。
6. 用户最新纠正覆盖旧结论；遗忘请求直接执行并登记；失效经验按月归档。
7. 仅报告新增、更新、归档或删除的条目 ID。

## 硬规则

- 不把工作人格偏好自动复制到娱乐人格，反之亦然。
- 新情境人格必须有持续价值；一次性情绪不单独建档。
- 潜意识假说必须保留其他解释和推翻条件，不得升级为事实。
- 对话历史只保存证据摘要与统计，不复制完整用户 Prompt 语料。
- 不保存秘密、完整对话或模型私有思维链，不将画像用于高影响决策。
- `.agents/memory/` 始终保持本地私有，不得提交到 Git。
