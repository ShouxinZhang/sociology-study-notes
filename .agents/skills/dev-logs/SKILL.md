# 单任务开发日志

把开发日志当作任务验收记录，而不是对话汇总。一个可独立验收或回滚的用户任务只写一份日志；用户用“Next”“顺便”“此外”等提出新的独立成果时，新建日志，不追加到旧日志。

## 任务边界

- 仓库文件变更、用户环境变更、数据清理和实质性故障诊断必须记录。
- 纯解释、闲聊和没有执行诊断的简短问答不记录。
- 同一业务目标的实现、测试、架构同步和日志收尾属于同一任务。
- 可独立验收、独立回滚或影响不同业务目标的工作必须拆开。
- 日志及索引的维护属于当前任务，不能递归创建“记录日志的日志”。
- 本规范生效前的历史日志按原样保留；不要仅为格式一致而迁移、改名或补造时间。

## 路径与命名

使用任务开始时间创建路径：

```text
docs/dev_logs/YYYY-MM/YYYY-MM-DD/HH-MM-SS+task-slug.md
```

`task-slug` 使用小写英文、数字和连字符。若同秒重名，在 slug 后追加简短序号，不覆盖已有记录。

## 工作流

1. 开始实际操作前，运行 `date '+%Y-%m-%d_%H-%M-%S %Y-%m %Y-%m-%d %H:%M:%S %z'` 固定任务 ID 和开始时间。
2. 从 [task-log-template.md](assets/task-log-template.md) 创建单任务日志，立即填写用户目标、方案边界与预期验收。
3. 执行过程中记录关键动作；完成后填写文件变更、验证证据、风险、回滚方式和最终成果。
4. 在当日 `README.md` 中增加一行任务链接；日期、月份或总索引不存在时按四层结构创建并只登记直属子节点。
5. 只有直属子节点变化时才更新直接父索引。根 `INDEX.md` 不登记任务明细。
6. 运行校验器：

```bash
python3 .agents/skills/dev-logs/scripts/validate_dev_logs.py \
  --root docs/dev_logs \
  --record docs/dev_logs/YYYY-MM/YYYY-MM-DD/HH-MM-SS+task-slug.md
```

7. 在最终回复中给出日志路径；若校验失败，先修复再交付。

## 内容要求

- 使用精确到秒、带时区的真实时间，不推测或伪造历史时间。
- 逐字记录触发当前独立任务的用户原始 Prompt；后续确认或范围修订也按消息顺序记录。
- 原始 Prompt 含密码、令牌、私钥或其他秘密时，用 `[REDACTED]` 替换秘密值并注明已脱敏，禁止把秘密写入仓库。
- 声明实际执行者的模型身份。只使用当前运行时或系统明确提供的产品与模型名称；无法确认具体子版本时不得猜测。
- 将原始 Prompt 与业务化的用户目标分开保存：前者用于审计，后者用于快速理解成果。
- 文件表只列本任务实际触及的路径，不把工作区既有脏文件算入本任务。
- 验证必须写命令或可复核证据，不能只写“已检查”。
- 没有仓库文件变更时明确写“无”；诊断任务仍需记录证据和结论。
- 删除或回滚任务必须记录 `.agents/cache/<task_name>/` 备份位置。

## 四层索引职责

```text
docs/dev_logs/INDEX.md
└── YYYY-MM/README.md
    └── YYYY-MM-DD/README.md
        └── HH-MM-SS+task-slug.md
```

- 总索引：月份级入口与汇总。
- 月份索引：直属日期入口与任务数。
- 日期索引：当天每个独立任务的时间、类型、状态和成果。
- 任务日志：唯一保存任务目标、动作、变更和验证明细。
